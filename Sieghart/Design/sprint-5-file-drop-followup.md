# File receiving — October 13 follow-up

Branch `sprint-5`. The user rejected the first receipt animation and requested automatic opening, following the dragged file and a background response like Coucou, with an original Sieg animation.

## Corrected behavior

- The collapsed camera activation zone and the expanded island both register an AppKit local-file drop destination. A file drag opens the Companion receiver immediately; ordinary pointer hover settings do not gate file drag. No global file-drag hook is installed.
- File reception belongs to Toni throughout hover, intake, processing and confirmation. Clearing file context restores the normal Sig Companion.
- Toni follows the file in both directions inside the receiver: left/right, up/down and diagonally. Her full silhouette stays within safe bounds. A coral radial light follows the same position, with a transparent dashed drop outline. Captions stay below the moving area. Toni is reduced from 132 to 72 points (45% smaller), including the user's final request for a further 25% reduction from the intermediate 96-point size; the moving area is 176 points tall, with the entire receiver retaining its previous 212-point height. The expanded body while dragging is reduced from 380 to 316 points; only a received-file or error card needs the taller 380-point body. The body keeps its own design; the moving aperture is inside its top silhouette rather than a rectangular slot across its face.
- A short intake moves the paper into depth behind the upper silhouette, closes the aperture and makes two restrained acknowledgement pulses. Rigid Ada/Gantt silhouettes remain rigid. The hovered open pose freezes after opening; it does not keep a SceneKit loop running while waiting for the drop.
- The original is represented by a security-scoped bookmark on the shared Shelf. A successful drop keeps an inline file card in the Companion with Preview, Files and clear-context actions. It does not automatically open a separate application or send/upload data. Remote chat/email execution is still the future integration layer, not a delivered consequence of attaching a file here.
- Hover-to-expanded transfer shares the drag sequence. A short exit debounce prevents flicker between the camera strip and the larger target. Abandoning the drag restores the previous page/visibility and preserves earlier attachments. A newer action is not replaced by a late read.
- URL delivery stays off the main thread with a bounded pasteboard worker and change-count ownership. Up to forty local file references are accepted; duplicates become one attachment. Metadata/reference admission is cancellable before Shelf commitment. The original file is not moved or deleted.
- Loading appears only when real bookmark/persistence work exceeds the intake. There is no cosmetic percentage bar. Reduce Motion or disabled character motion uses a stationary receiver and skips the artificial animation wait.

Current scope is native `.fileURL` drags such as Finder files/folders. Promised attachment data from apps that do not expose a local file URL is a separate adapter. Context persists while the app runs until cleared; kept Shelf references persist independently.

## User test

1. Quit the older build and open the current one. Leave the widget closed and drag a Finder file over the camera/island activation area: it should open without clicking or first opening Shelf.
2. Keep holding and move left/right, then straight up/down and diagonally. Toni and the radial light should follow together inside the outlined receiver without crossing its edges or covering the captions. Test all widget sizes; a vertical-only drag must not move her horizontally. There should be no second floating file during hover and no front-face rectangle.
3. Drop. The paper enters through the top, Toni settles centrally and the filename/card appears. Preview and Files must resolve the same original. Repeat with two files and repeated copies of one file.
4. Drag again and leave/cancel before release. The old attachment and previous page must remain available. Move quickly from the camera strip into the receiver; it must not close or flash midway.
5. Interrupt an intake with another page or a newer drop. The older task must not pop its context over the new one. Test in fullscreen and with the main window closed by its red button.
6. Turn off motion/enable Reduce Motion: the target stays centered and receiving should not wait for the choreography. Compare whole-app CPU during drag, receipt, idle and after hiding; the source/rig tests do not establish live CPU.
