## Delivered in this slice

### Clipboard

- One shared local history in the main app, bounded island and menu-bar Clipboard subpage. The default side-button preset includes Clipboard; **Control + Option + C** opens it globally through the resident shortcut controller.
- Explicit opt-in, text/images/file references, search, type filters, pins, preview, Copy/Paste, delete, pause/resume, exclusions and confirmed clear. File contents are not copied into history; references remain at their original locations.
- Choose **5, 10 or 20** saved copies (default 20). Pins count toward that limit. Choose cleanup **after 1–365 days**, **when the Mac shuts down**, or **when the notebook lid closes**. Age cleanup preserves pins; shutdown/lid cleanup clears pins too. The 40 MB payload ceiling still applies.
- Clipboard polling runs off the main thread with a bounded worker and timeout. Enabling/resuming starts from a fresh baseline, so an earlier copy is not silently captured. Concealed/transient/autogenerated copies and configured password-manager sources are skipped. Source names represent the foreground app at capture time, not proven clipboard ownership.
- Atomic local persistence in `~/Library/Application Support/Sieghart/Clipboard/history.json`, directory mode 0700/file mode 0600, bounded restore, revision checks and expiration pruning on restore/capture/settings and once per minute while running. No upload, telemetry or credential access.
- Copy works without keyboard permission. Direct Paste requests Accessibility only through an explicit user action, restores the previous external app, checks focus and clipboard again before sending ⌘V, and falls back to a truthful Copy/⌘V instruction if unavailable. Clipboard history itself needs no Accessibility grant.
- Shutdown cleanup listens to macOS power-off and flushes before orderly application termination; a boot-time check also clears retained history after a restart. Lid cleanup observes the actual clamshell property through polling and a sleep-time read. Sleep/lid behavior and abrupt system termination remain physical acceptance cases; no promise of hardware validation is made by isolated tests.

### Companion and onboarding motion

- Welcome → six-character selection → optional local tools. Existing avatar choices and local consent remain preselected; core companion/timers work offline.
- Native 60 Hz arrival with damped movement, squash, soft nod and eyes opening. No new bitmap character, external animation asset or black strip above the onboarding avatar. Pointer gaze is centered on the actual view width and reaches both left and right.
- Optional **Set up voice access** prepares microphone/speech permissions without starting recognition or audio capture. **Set up direct paste** prepares Accessibility when clipboard is chosen. Setup can be skipped and completed when using a feature later.
- Finish saves the chosen avatar and tools, then opens Companion with a distinct 0.9-second shell reveal and delayed avatar arrival. Focus does not start. Normal openings keep their existing timing. Motion respects macOS/custom Reduce Motion and Character motion settings; pointer-exit collapse remains.
- The six approved Simple Companions retain their names, palettes, native matte depth and existing blink/breath/sleep/touch expressions. File receive/carry and specialist-agent reactions remain later work, tied to real tasks.

### AI spending correction

The reference's data path was inspected: the resources contain numeric API price facts, while log parsing/pricing live in services. Sieghart retains its own parser and directly fetched official price catalog.

- Recognize `token_usage_record` and its response ID. Request records take precedence over repeated cumulative quota events; cloned responses deduplicate by their identity.
- Read `thread_settings_applied` speed changes and retain the actual Fast/priority price tier. Prefix/case normalization preserves the model's documented price rather than inventing a family price for internal models.
- Automatically scan each eligible recent file on first discovery (up to 64 MiB per file and 512 MiB per cycle), then merge updates with earlier retained counters. The previous 2 MiB-only initial read discarded earlier token events from long conversations. Individual files/counters/discovery stay bounded; source coverage remains visibly partial.
- Input includes cache reads/writes, output includes reasoning, cache is not added twice, and long-context pricing uses request input rather than a session aggregate. Numeric standard/cache/write/Fast facts were compared with the reference and the current official OpenAI table.
- Spending uses a quieter value/metadata hierarchy and exact unpriced-token disclosure in place of a generic orange badge. It remains **API equivalent**, not the user's subscription charge. `codex-auto-review` has no published price in the inspected reference either; it remains unpriced. Recorded invoice charges stay separate.

## User Mac checklist

1. Open the updated build. In **Overview → Review introduction**, choose a companion and local tools. Optionally prepare voice/paste access; finish. The widget should open once with the softer arrival, use that avatar, start no focus, and collapse on pointer exit. Move over the avatar from both sides. Repeat with Reduce Motion.
2. Enable **Clipboard → Save history**. Copy different text, an image and a Finder file. Use **⌃⌥C** in another app; search, filter, pin, delete and Copy. With Accessibility granted, Paste should target the app used immediately before Sieghart. Denying access must leave Copy/⌘V available. Close the main window and repeat the shortcut in full screen.
3. Clipboard settings: choose 5, copy 6 distinct values, expect at most 5. Change to 10/20 and check across relaunch. Verify day cleanup with an aged test item if available; pins survive age cleanup. Select lid cleanup, close/reopen the lid and confirm empty history. Select shutdown cleanup, save a copy, shut down/restart and confirm empty history. Changing the policy should persist; closing only the app window should not clear it.
4. **Dynamic Island**: click a surrounding button to edit/remove, click + to add Clipboard, drag occupied-to-occupied (swap) and occupied-to-empty (move), and try Layout presets. Select Small/Medium/Large, click the bottom avatar to change it, reopen the widget and relaunch. Every remaining button should keep the chosen position and action. Appearance → Edit layout should navigate here.
5. **Activation → Three-finger middle click**: initially off. Enable, allow Accessibility, retry. Tap with three fingers on a browser link to request middle click; the receiving app defines the result. Two/four fingers, moving/dragging and holding must not generate it. Disable and verify it stops. macOS three-finger Look Up/Drag settings may conflict.
6. **AI agents → Today**: refresh/allow monitoring and compare the same day's model/input/output/cache records and speed tier. Unknown/internal models must show an unpriced count, not a made-up cost. Source limits still prevent claiming complete account-wide billing.

## Optional three-finger utility

An original recognizer rejects movement, long taps, excess fingers and duplicate releases. The runtime dynamically loads macOS's undocumented contact interface only after opt-in and Accessibility, stops on disable/sleep/lock and rejects stale callbacks. Missing framework/device support displays unavailable. This is a **Mac utility only**; the future Student Challenge package must omit it. The user accepted this slice’s hardware checks on October 8. This implements a three-finger tap, not three successive clicks. It does not change macOS gesture preferences or promise Windows-style autoscroll in every app.
