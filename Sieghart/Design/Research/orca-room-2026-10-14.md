# Conversation office and Orca reference

October 14, 2026. The user's reference depicts agents at desks. The latest correction asks for several small rooms to choose a conversation, plus a square to create another chat. Each room follows that conversation's real nested agents; clicking the room opens its chat.

## Reference

[Orca sessions](https://www.onorca.dev/docs/model/agents-sessions) uses a parent session with expandable child agents, shared state glyphs, task previews and a click through to the worker. [Orca orchestration](https://www.onorca.dev/docs/cli/orchestration) separates task, dispatch, coordinator and completion authority. These are organizational references. No Orca runtime connection, copied code, terminal-autonomy flags or art are incorporated.

## Delivered structure

- A compact gallery of five conversation rooms per page plus a permanent **+ New chat** tile. Each room has a miniature office, Ada and its own workers. Five reusable 2D worker silhouettes (capsule, pixel body, folded paper, soft drop and faceted pebble) cycle as workers enter; each worker's pastel color is stable for its runtime ID. Empty desks indicate unused capacity. Each room thumbnail shows up to six characters and a remainder count; the chat's activity strip exposes worker details.
- The selected conversation controls room membership. Worker ID, root ID and parent ID group nested agents without mixing other conversations. Clicking a character shows its actual assignment and latest reported activity. Codex child threads can open their own chat; Claude tasks return to their main Ada conversation.
- Visible working rooms use one shared sparse pose clock. Ada's chat reactions use cached art and Core Animation, with a brief idle gesture every 8.5 seconds and no continuously changing idle layer. Hidden/inactive/reduced-motion views stop playback. Static floor drawing and 2D workers avoid a live 3D scene per worker.
- Codex uses `parentThreadId`/thread-spawn metadata and `collabAgentToolCall` receiver IDs, assignments and `agentsStates`. A completed collaboration RPC is not a completed worker. Fallback nicknames use the actual identifier.
- Claude uses SDK task start/progress/update/notification events. Only agent tasks create figures; background shell tasks do not. Run IDs reject a previous run's late completion. Child messages update that figure's activity rather than polluting the main transcript. Ending a query marks the child's last report as historical rather than pretending it finished.
- For existing Codex executions, the selected tree's persisted spawn edges discover children missing from the recent conversation page. Turn states remain authoritative even during long silent commands or when a later content timestamp follows completion. Reads run on a utility task; the compatibility reader is bounded to 64 identities / eight levels, with up to 24 persisted parent messages and two per child. Legacy rollout reads process only appended complete records, start with at most 256 KiB and cap subsequent reads at 64 KiB per file. Unchanged files are not reparsed. Rooms/chat check at three-second intervals and refresh recent identity metadata at nine-second intervals, with at most 32 legacy files. Observation does not resume or start a turn. Completed states remain completed rather than being kept active by content timing.
- Sending to a desktop-owned root uses [Codex's queue handler](https://github.com/openai/codex/blob/main/codex-rs/app-server/src/request_processors/thread_queue_processor.rs) and [revision watcher](https://github.com/openai/codex/blob/main/codex-rs/ext/queue/src/service.rs), preserving the existing writer. An active-writer conflict falls back to the same queue path. Queue client identity is normalized against persisted user-message `clientId`, preventing duplicate bubbles. Queue acceptance does not claim execution or completion. Direct child input is read-only; the UI explicitly opens the parent to give another instruction.
