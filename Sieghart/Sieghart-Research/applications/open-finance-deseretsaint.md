# Open Finance — DeseretSaint (aplicação prioritária 3)

**Data:** 13/10/2026. **Fonte fixada:** [`DeseretSaint/open-finance` no commit `94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26`](https://github.com/DeseretSaint/open-finance/commit/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26), versão declarada `0.3.49`. Esta etapa leu código, migrações e documentação oficiais. **Não houve instalação, execução, carga de dados financeiros nem teste de exploração.** Problemas de autorização abaixo são conclusões de fluxo de código, para confirmar em teste isolado antes de qualquer uso com dados reais.

## 1. Identidade, manutenção e decisão provisória

**Verificado:** é um aplicativo de finanças pessoais hospedado pelo usuário, com interface web Next.js/React, servidor Node, banco SQLite, variante Android Capacitor e modo web solo. No macOS, o [instalador oficial](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/scripts/install.sh#L1-L43) baixa o código de `main`, instala dependências, compila e abre `localhost:3000` no navegador; não entrega uma UI nativa Swift/AppKit. A licença do projeto é [MIT](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/LICENSE). O [pacote](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/package.json#L1-L60) declara Node 22, pnpm 11, Next 15.5, React 19, Plaid, SDK MCP, `better-sqlite3`, `sql.js` e Capacitor.

O último commit de `main` analisado é de **28/08/2026**, e a [release `v0.3.49`](https://github.com/DeseretSaint/open-finance/releases/tag/v0.3.49) foi publicada no mesmo dia. Havia 11 PRs abertos, principalmente atualizações automáticas de dependência, na consulta de 13/10/2026. Execuções automatizadas em outubro no mesmo SHA não demonstram nova versão do produto. Isso indica um projeto recente com implementação substancial, mas não comprova suporte contínuo ou revisão externa de segurança. [Histórico](https://github.com/DeseretSaint/open-finance/commits/main/), [releases](https://github.com/DeseretSaint/open-finance/releases), [PRs](https://github.com/DeseretSaint/open-finance/pulls).

**Decisão para Sieghart:** aproveitar o **modelo conceitual** de escopos, tokens, pedidos de permissão e trilha de acesso, corrigindo as lacunas apontadas adiante em um desenho original Swift. **Não integrar o servidor ou banco deste projeto ao Sieghart nesta fase.** A investigação independente do segundo projeto e a [comparação final](open-finance-comparison.md) foram concluídas depois deste dossiê.

O especialista Sieghart deve recusar ou qualificar uma resposta quando faltar dado, nunca fabricar registros.

## 3. O modelo de agente e MCP realmente implementado

O [`AgentTokenService`](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/authz/tokens.ts#L1-L181) cria Bearer token com hash SHA-256 no banco, prefixo visível, escopos, validade, revogação e lista opcional de contas. Há presets `read-only`, `read-all` e `read-write`. O conjunto efetivo é calculado em cada chamada como **escopos do token ∩ limites atuais das preferências**; um token `follow_settings` acompanha os limites em ambas as direções. [Autorização REST/MCP](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/authz/agent-auth.ts#L57-L103), [preferências](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/domain/agent-prefs.ts#L103-L145).

**Padrão verificado:** preferências de agente permitem inicialmente só leitura da aba Activity (`read:banking`), sem escrita; `autoApproveReads=false`, `requireWriteConfirm=true`, `auditEnabled=true`. O preset de token `read-only` contém mais escopos, mas a interseção reduz o acesso efetivo. [Defaults](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/domain/agent-prefs.ts#L103-L145), [presets](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/authz/tokens.ts#L13-L55).

O servidor MCP usa **Streamable HTTP** em `/mcp`; o [CLI](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/scripts/mcp-cli.mjs) oferece transporte stdio para outros agentes. O [registro de ferramentas](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/authz/route-registry.ts#L96-L161) liga nome, escopo e endpoint. O [dispatcher MCP](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/mcp/server.ts#L653-L730) autentica, verifica escopo e valida argumentos com Zod antes de executar. A [rota HTTP](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/app/api/mcp/route.ts#L118-L177) captura o Bearer token para cada chamada. A falta de escopo cria pedido de permissão deduplicado e auditável; aprovação exige sessão do usuário e CSRF. [Pedido](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/authz/permission-requests.ts#L43-L71), [resolução](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/app/api/agent/requests/%5Bid%5D/resolve/route.ts#L14-L25).

**Limites positivos:** o [registro REST](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/authz/route-registry.ts#L6-L83) mantém criação/remoção de contas e exclusão de transações fora da API de agentes; não há ferramenta de transferência financeira no [catálogo MCP](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/authz/route-registry.ts#L96-L161). `trigger_sync` inicia sincronização, mas não pagamento. O botão de marcar uma fatura como paga altera registro interno; não é uma operação bancária demonstrada. Isso é uma fronteira útil para o Sieghart.

## 4. Lacunas de segurança verificadas no fluxo de código

As conclusões a seguir se referem **somente ao commit fixado**, sem execução com tokens reais. Elas exigem correção e testes de regressão antes de considerar integração com dados pessoais.

1. **Lista de contas não propagada em leituras por ID.** A ferramenta MCP [`get_transaction`](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/mcp/server.ts#L199-L209) e a [rota REST equivalente](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/app/api/transactions/%5Bid%5D/route.ts#L21-L29) chamam `transactions.get(userId,id)`. A [consulta](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/domain/transactions.ts#L120-L132) filtra `user_id`, mas não os IDs de conta autorizados nem o tipo bancário/investimento. Um agente que conheça o ID de uma transação da mesma pessoa poderia ler uma conta excluída da sua lista. O [PATCH](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/mcp/server.ts#L348-L359) também usa `transactions.update` → `get` sem esses filtros.
2. **Filtro por tipo de conta inconsistente.** [`list_accounts`](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/domain/accounts.ts#L75-L108) separa `read:banking` de `read:investments`; já [`list_transactions`](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/domain/transactions.ts#L49-L117) aceita a lista opcional de IDs, mas não filtra `accounts.type`. Como o [MCP aceita qualquer um dos dois escopos](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/mcp/server.ts#L653-L665), um token limitado a um tipo pode ver transações do outro quando `account_ids` é nulo. A rota REST de lista repassa a lista de IDs, mas tampouco fornece filtro de tipo. [Rota REST](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/app/api/transactions/route.ts#L37-L56).
3. **Relatórios MCP ignoram a lista de contas.** [`get_spending_by_category`, `get_cashflow` e `get_net_worth`](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/mcp/server.ts#L314-L345) chamam serviços sem `allowlist`, embora os [serviços aceitem o parâmetro](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/domain/reports.ts#L13-L22) e as [rotas REST o passem](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/app/api/reports/net-worth/route.ts#L10-L17). `get_planning_items` inclui uma [projeção](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/domain/projection.ts#L47-L65) de todas as contas do usuário e não recebe lista de contas. A permissão `read:planning` portanto pode expor totais fora do subconjunto autorizado.
4. **Confirmação destrutiva anunciada não aparece no dispatcher MCP.** O [guia](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/docs/AGENTS.md#L108-L129) afirma que `requireWriteConfirm` pede aprovação explícita antes de exclusões. A preferência é guardada em [`agent-prefs.ts`](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/domain/agent-prefs.ts#L98-L113), mas o [dispatcher](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/mcp/server.ts#L680-L730) verifica escopo e chama a ferramenta, e [`delete_budget`](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/mcp/server.ts#L406-L415) remove o orçamento diretamente. O pedido de permissão é disparado quando **falta escopo**; com `budgets:write` concedido, não há confirmação por operação nesse caminho. O mesmo padrão vale para `delete_category` e `delete_custom_view` examinados. Não afirmar que todos os caminhos de UI compartilham esse comportamento.
5. **Chave global ampla; campo de escrita separado sem efeito nesse ramo.** Em [`capScopes`](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/domain/agent-prefs.ts#L124-L145), `prefs.global=true` adiciona todos os escopos de leitura **e escrita**, sem consultar `globalWrite`. O próprio [teste](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/tests/agents.test.ts#L24-L45) documenta a escolha; o comentário da [migração 007](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/migrations/007_agent_access.sql) ainda descreve `globalWrite` como subalternância. A UI deve mostrar o alcance real da chave global.
6. **Auditoria configurável e de melhor esforço.** O [MCP registra sucessos após executar](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/mcp/server.ts#L710-L730) se `auditEnabled`, ignorando falha de gravação. Chamadas negadas são registradas no fluxo de permissão. Assim, “auditoria completa” é uma intenção configurável, não garantia transacional de cada efeito. A [API REST de capacidades](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/app/api/agent/capabilities/route.ts#L17-L47) também informa escopos crus do token, não a interseção efetiva da configuração atual.

**Escopo do achado:** não foi feito teste dinâmico, revisão de todos os caminhos de autenticação ou auditoria independente do projeto. O [arquivo de auditoria mantido no próprio repositório](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/SECURITY-AUDIT-2026-08-07.md) é anterior à revisão fixada e deve ser lido como relato dos autores, não certificação de segurança. Reutilizar conceitos após corrigir fronteiras em testes separados é diferente de confiar no serviço atual para dados sensíveis.

## 5. Privacidade, armazenamento e promessas de criptografia

O [README](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/README.md#L1-L35) descreve “SQLite + AES-256-GCM encryption at rest”. O código confirma **cifragem de campos específicos** de credenciais/tokens Plaid pelo [envelope AES-GCM](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/lib/crypto.ts#L10-L41) e dos [arquivos de backup](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/domain/backup.ts#L9-L84). **A base financeira ativa não aparece cifrada pela aplicação:** o servidor abre o arquivo com [`better-sqlite3` comum](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/db/adapter.ts#L1-L27); o adaptador Android cria conexão em modo [`no-encryption`](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/db/cap-sqlite.ts#L42-L69); o modo web exporta bytes SQLite para [IndexedDB](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/db/browser-sqlite.ts#L3-L20). Criptografia do volume/dispositivo do sistema operacional é uma camada distinta e não foi medida aqui.

O [bootstrap](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/env-bootstrap.ts#L3-L66) pode gerar `ENCRYPTION_KEY` e `AUTH_SECRET` em `data/.env.keys`; esse arquivo e o banco exigem proteção operacional e backup apropriados. O código usa Plaid com credenciais fornecidas pelo usuário e processamento externo do provedor; portanto, “auto-hospedado” se refere ao aplicativo/banco, não a todas as integrações bancárias. A [origem Plaid](https://github.com/DeseretSaint/open-finance/blob/94d4a7e8ea875d346f5fd3d231ae1a022ddb6a26/src/server/plaid/real.ts#L39-L50) depende de um serviço externo.

## 6. Padrões úteis para uma arquitetura original do Sieghart

**Proposta, ainda sem implementação:** manter Elinor como especialista financeiro já existente em [`CompanionAvatars.swift`](../../Sieghart/Shared/Components/Companion/CompanionAvatars.swift), com um serviço Swift próprio de dados financeiros. Definir escopos como `ReadAccounts`, `ReadTransactions`, `ReadBudgets`, `AnalyzeExpenses`, `GenerateReports`, `ProposeBudgetChanges` e `ModifyBudgetsWithApproval`. O nome de qualquer novo agente fica pendente; não duplicar Elinor automaticamente.

Cada operação do especialista deve receber **identidade da tarefa, fonte consentida, IDs de conta autorizados, classes de dado, tipo de operação e prazo**. O mesmo filtro deve atuar em consultas de lista, por ID, agregações, projeções e escrita; uma autorização de leitura não deve permitir alterar dados. Escopos financeiros devem ser verificados no ponto de execução, não apenas na lista de ferramentas. Alteração de orçamento precisa gerar proposta com valores anterior/novo e aprovação daquela operação; uma concessão ampla não substitui esse passo. Transferências de dinheiro e ordens de investimento permanecem fora do escopo padrão.

Armazenar valores como `Money(amountMinor, currency)` e oferecer totais por moeda. Conversão exige taxa, data, fonte e moeda-base, com estimativa identificada; jamais somar centavos de BRL, EUR e USD como se fossem a mesma unidade. Cada resposta natural deve apontar período, contas incluídas, fonte, atualização e lacunas. CSV/OFX importados pelo usuário e integrações reguladas brasileiras serão avaliados em etapa própria após os dois repositórios, sem presumir acesso bancário direto. Para um futuro protótipo, proteger o banco inteiro ou documentar claramente a proteção do volume e a cifragem de campos, e testar restauração/exclusão de dados.

## 7. O que permanece desconhecido e próximo portão

- Funcionamento real do projeto no macOS deste usuário; nenhuma instalação ou medição de CPU, memória, bateria ou latência.
- Exploração dinâmica das lacunas de autorização citadas; o fluxo está demonstrado em código, o efeito prático deve ser reproduzido com contas e tokens sintéticos em ambiente isolado.
- Qualidade de sincronização Plaid com instituições específicas, custos/termos do provedor e disponibilidade para o Brasil; o adaptador examinado usa `CountryCode.Us`.
- Estratégia de câmbio, holdings de investimento, importação OFX e classificação de assinaturas além do que a árvore e os caminhos citados mostram.
- Comparação com `openfinance-app/open-finance`: era desconhecida **nesta etapa independente**; foi concluída posteriormente na [comparação](open-finance-comparison.md).

**Estado do tópico:** pesquisa estática independente de `DeseretSaint/open-finance` concluída. Nenhum código Sieghart foi modificado; não há passos de teste de produto agora.
